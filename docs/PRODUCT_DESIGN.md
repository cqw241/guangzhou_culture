# 数智读广州｜AI 赋能广州城市文化数字传播平台设计说明书（V1.0）

> 项目定位：数字文化理解平台，而非传统旅游行程工具。2026-10-22。
> 原始内容来自本仓库《创意背景.md》与 `路线景点文档/` 四条线路资料，演示页见 `demo/index.html`。

## 1. 从第一性原理推导产品

**终极任务**：让具有不同语言、知识背景的用户，在有限注意力与时间内，对广州文化产生可验证的理解，并愿意进一步探索、交流和分享。

**基本事实与约束**：
1. 用户并不天然需要“景点”，而是希望解决“我该看什么、为什么重要、与我有什么关系”。
2. 文化价值依赖 **人—事—物—时—地—因果关系**，仅罗列点位不会自动产生理解。
3. 语言转换不等于意义转换。面向不了解中国历史的读者，必须解释政治制度、宗族、商贸制度等概念。
4. AI 可以降低检索和解释成本，但模型生成概率不是史实真实性。权威数据源、版本与引用高于流畅回答。
5. 手机是主要界面，应先满足快速进入、轻量探索、单手操作和低带宽环境；视觉表现不能妨碍阅读。
6. 四大文化主题与线路、中文/英文、互动机制、AI 场景和提交物是赛事刚性约束。

**价值公式（设计假设，非统计事实）**：

`有效传播 = 发现率 × 理解率 × 可信度 × 继续探索/分享意愿`

任何一个环节接近零，其余环节优化都难以弥补。因此首版优先级为：内容可追溯 → 四线可探索 → 双语可理解 → 自由问答 → 多模态特效。

## 4. 核心产品结构

```text
发现 / DISCOVER
 ├─ 首屏一句话价值与探索入口
 ├─ 四大主题文化入口
 └─ 带来源的精选故事
探索 / EXPLORE
 ├─ 四条主题数字路线
 ├─ 13个叙事篇章（原资料主题日）
 ├─ 路线节点与场景关系概览
 └─ 单节点深度阅读
理解 / UNDERSTAND
 ├─ 四个中英策展案例
 ├─ 文化概念桥接（跨语言表达策略）
 └─ 历史原文/来源提示
问答 / ASK
 ├─ 用户自然语言问题
 ├─ 本地文化数据检索
 └─ 匹配文本 + 资料链接 + 不确定性声明
资料库 / LIBRARY
 ├─ 61个节点搜索
 ├─ 主题筛选
 └─ 节点详细内容
```

**主路径**：进入首页 → 选择文化主题 → 阅读叙事导语 → 选择篇章 → 打开文化节点 → 阅读内容与来源 → 对照英文文化解读 → 发起追问 → 返回主题探索。

地图策略：演示原型当前为 **示意性的空间关系模块**，不是真实地图，未接入坐标、地图SDK、GIS或导航。下一阶段应由专业地图平台提供地点坐标及经核验路线，明确区分“文化叙事顺序”和“地理最短路径”。

## 5. 四条叙事线（选题设计）

### A. 红色文化——“城市中的变革记忆”
原资料19点、4篇章：近代抗争与辛亥革命 → 国共合作与工运浪潮 → 起义与军事教育 → 近代建筑和对外接触（最后一组拟经专家复核重组）。
主要思考：一座城市如何留下历史变革中的公共记忆？
样例：黄花岗七十二烈士墓园。英文内容补充1911革命运动背景与纪念的公共历史意义。

### B. 创新文化——“广州如何不断重新发明自己”
原资料8点：白天鹅宾馆、开拓者雕像、天河双子塔、广州塔、海心桥、永庆坊、北京路、大学城。**这一条更适合按“制度创新 → 城市建设 → 城市更新 → 知识创新”而非“地理一日走完”理解**。
样例：白天鹅宾馆。英文解释中国改革开放的政策背景，再说酒店的象征意义。

### C. 岭南文化——“日常生活里的美学与技艺”
原资料19点、4篇章：建筑园林 → 民俗工艺 → 当代融合 → 山水与市井饮食。
样例：陈家祠。说明“祠堂/书院/宗族与工匠空间”，不机械译为 temple。

### D. 海上丝绸之路文化——“广州如何连接世界”
原资料15点、4篇章：早期港口 → 唐宋海贸与宗教交流 → 明清商贸 → 当代海运。
样例：十三行博物馆。解释行商、广州贸易体系，避免字面译成 thirteen streets 或 thirteen shops。

**路线选点原则**：主题相关性（35%）+ 因果/时代关系（25%）+ 样本代表性（20%）+ 跨文化解释潜力（15%）+ 素材可验证性（5%）。这是建议的人工评审权重，不是算法训练参数。文化叙事顺序不承诺当日旅行可行。

## 6. AI 产品设计：从可信检索出发

本次可运行演示使用 **本地检索式问答**：用户提问后从61节点进行关键词匹配，优先显示4个经人工编排的双语解释，其余返回来源标注的资料包摘要。如果无法匹配，主动拒绝杜撰。**这不是在线大模型或真正的 RAG**。

可扩展的正式 AI 架构：
1. 资料导入：原始网页 / Markdown → 元数据解析 → 去重 / 同名实体合并 → 权威出处核验 → 版本化内容库；
2. 表达：Node（点位）、Event（事件）、Person（人物）、Period（年代）、Theme（主题）、Source（来源）、Narrative（已审核文案）、Media（授权媒体）；
3. 检索：关键词 + 向量混合检索；按语言、主题、时段、来源权威等级过滤；
4. 生成：仅允许依据检索片段生成解释；工具返回 `source_id`、证据定位、数据版本；
5. 审核：历史断言校验、敏感实体检查、跨文化编辑审阅；必要时进入“原文直读”；
6. 反馈：错误报告 → 专家复核 → 内容修订 → 重新索引。

**守则**：回答必附来源；不同来源冲突时显式注明；古今空间变化、年份、人物关系不能凭语言模型推断；开放时间、票务、交通依赖实时信息且需单独接入；未获授权的图片不用于商业公开部署。

推荐采用人工策展卡 + 机器辅助改写的混合模式。高价值故事由编辑确认，AI 负责检索、长度适配和语言解释，不允许自动“修正历史”。

## 7. 国际传播（中英为基础）

四个节点已实现独立英文文化文本和“为什么如此解释”的编者说明，详见 `demo/data.json` 的 `highlights`。

| 语义难题 | 不建议 | 推荐 |
| --- | --- | --- |
| 辛亥革命 | 仅音译 Xinhai | 先交代 1911 revolutionary movement 与帝制终结 |
| 改革开放 | 空泛直译 | 加上自1970年代末开始的政策与城市变化语境 |
| 陈家祠 | 仅译 temple | 解释 clan、ancestral hall、academy 和 craft |
| 十三行 | thirteen shops | 解释清代广州贸易体系下的行商机构 |

正式版本必须：术语双语表、译者/审核者、时间版本、文化敏感性审阅；主站切英文后，**未翻译的原始节点明确保持中文，而不是假装已翻译全部资料**。

## 8. 交互与视觉

移动优先；顶部语种按钮、底部五项导航；首页英雄区以抽象珠江与城市天际线为符号；主色为岭南草木绿、温润米白与历史金；衬线字传达文化厚度，无衬线字保证移动阅读清晰。交互包括主题切换、篇章筛选、节点弹层、全文检索、主题筛选、双语切换、可引用问答。提供键盘交互、基本文本替代与减少动画偏好支持；正式上线前仍需 WCAG 可用性专项测试。

| 阶段 | 时间建议 | 工作 | 验收 |

以上为**拟定验收目标**，尚未做用户实验和技术实测。

实验设计：至少招募国内文化爱好者与英语使用者各5–8名，使用统一任务：识别陈家祠文化用途、找到对应主题路线、解释十三行、检索并打开原始来源。衡量完成率、理解题正确率、来源定位成功率、系统可用性与主观理解程度。比较“传统景点简介”与“跨文化解释卡”的理解效果。

## 12. 风险与明确边界

1. **真实性**：项目数据带有百科链接，但百科与历史概述不等同于权威文物证明；必须按节点完成专家复核。
2. **归类与顺序**：保留仓库主题日是为继承资产，不代表推荐用户按顺序实地打卡。
3. **地图**：当前仅示意图，没有经纬度，不可作为导航。
4. **AI**：当前为离线关键词检索，不代表部署了语言模型。
5. **版权**：仓库图片未经逐一核定传播及再利用授权；公开使用前确认。
6. **隐私**：首版无用户账户和持久化个人画像，查询在浏览器端完成；正式接第三方模型需另行评估数据传输与告知机制。
7. **无障碍**：界面支持部分键盘路径，尚未完成读屏器与对比度完整审计。

**核心判断**：平台的壁垒不是“AI 帮你介绍景点”，而是基于广州独特文化资源的、可追溯且跨文化可理解的城市知识叙事系统。
